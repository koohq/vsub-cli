# テストおよび品質検証規範 (Testing & Quality Rules)

本プロジェクト（`vsub-cli`）では、トークン消費の抑制と開発高速化、および最終成果物の高品質担保を両立するため、以下のテスト・検証ルールを定めます。

## 1. 作業途中の全体検証（フルテスト・全型検査・全リント）の乱発禁止
- **禁止事項**:
  - 実装・修正の途中で `pnpm run test`, `pnpm run check`, `pnpm run build` 等のプロジェクト全体を対象とするコマンドを手動で繰り返し実行してはならない。
  - 出力ログの肥大化によるトークン浪費と不要なターン消費を防ぐため。
- **推奨される動作確認**:
  - 作業途中の動作確認は、**変更を加えた対象ファイル単体のテスト**（例: `pnpm exec vitest run src/srt.test.ts`）に絞って実行すること。

## 2. 最終品質ゲート（Stopフック）への自動委譲
- プロジェクト全体の整合性検証（フォーマット・型検査・リント・全単体テスト）は、作業完了時（Stopフック）にバックグラウンド実行される `.agents/scripts/quality-gate.mjs` に一任する。
- 実行パイプライン:
  1. `pnpm run format`（Biome による自動フォーマット修正）
  2. `pnpm run build`（TypeScript による厳格な型整合性チェック）
  3. `pnpm run check`（Biome による構文・リント検証）
  4. `pnpm run test`（Vitest による全単体テストスイート実行）
- いずれかのステップでエラーが発生した場合は、Stop フックによって自動的にエラー内容と共に差し戻されるため、エージェントは差し戻されたエラーのみをピンポイントで修正する。

## 3. 単体テストの実装ルール
- **機能追加・バグ修正時**:
  - 対応するテスト（`src/*.test.ts`）を必ず追加・更新すること。
- **外部依存のモック化**:
  - Groq API、Gemini API、FFmpeg 外部プロセス（`execa`）等は `vi.mock` を用いてモック化し、オフラインかつミリ秒単位で高速実行できるようにすること。
